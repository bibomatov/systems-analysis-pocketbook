# Как внести вклад

Спасибо за интерес к книге. Здесь — короткие правила, чтобы ваш вклад быстро попал в основной репозиторий.

## Что принимается

- **Исправление опечаток, ошибок, неточностей** в существующих главах
- **Уточнения формулировок** в существующих темах
- **Предложение новых тем** в рамках утверждённого каркаса (см. [редакционный стандарт](meta/editorial-standard.html), § 03)
- **Технические улучшения** скрипта сборки, CI, дизайн-системы
- **Правки SVG-схем** при обнаружении неточностей

## Что не принимается без предварительного обсуждения

- Новые главы и крупные структурные изменения каркаса книги
- Изменение редакционного стандарта или дизайн-системы
- Англоязычные источники в блоке «Дополнительные источники»
- Использование AI-сгенерированного текста без редактуры по редстандарту

Перед такими правками — откройте issue с описанием идеи. Обсуждение займёт меньше времени, чем переписывание PR.

## Процесс

1. **Issue или PR.** Мелкие правки (опечатки, формулировки) — сразу PR. Содержательные правки — сначала issue.
2. **Ветка.** Имя ветки латиницей в kebab-case: `fix/typo-chapter-04`, `feat/glossary-saga`, `docs/contributing-guide`.
3. **Коммиты.** Сообщения на русском языке в формате `тип: описание`. Типы: `глава`, `правка`, `доки`, `инфра`, `стиль`, `ассеты`, `глоссарий`. Подробнее — в `meta/project-instructions.md`.
4. **PR.** Заголовок и описание на русском. В описании — что изменено и зачем.
5. **Проверка.** CI автоматически запускает `python3 build.py --check` и валидирует синхронизацию TOC. PR с упавшим CI не принимается.

## Стилевые требования

Все правки контента должны соответствовать [редакционному стандарту](meta/editorial-standard.html). Ключевое:

- Тон: профессиональный, без академической сухости и без разговорной фамильярности
- Лексика: минимум англицизмов там, где есть устоявшийся русский эквивалент
- Структура темы: один из трёх шаблонов (полный, средний, краткий)
- Источники: только русскоязычные
- Принцип материальности: абстрактные концепции привязаны к материальной форме

При несоответствии стилю автор может попросить переработать формулировки перед слиянием.

## Технические требования

- Маркеры в HTML-файлах (`<!-- CHAPTER-CONTENT-START -->`, `TOC-GLOBAL-INCLUDE` и т. д.) — не удалять и не переименовывать
- ID элементов — по конвенции из редстандарта (§ 12): `ch-NN`, `ch{NN}-{slug}`, `gloss-{slug}`
- В HTML использовать двойные кавычки для атрибутов, без пробелов вокруг `=`. Пример: `<a href="...">`. Это нужно для надёжной работы `build.py` при преобразовании ссылок в собранную книгу
- Перед коммитом — `python3 build.py --check`. При изменении структуры глав — `python3 build.py --sync-toc`
- Не коммитить `pocket-book.html` — он генерируется автоматически

## Локальная разработка

```bash
git clone <repo-url>
cd pocket-book-sa
python3 build.py --check   # валидация
python3 build.py           # сборка pocket-book.html
open pocket-book.html      # macOS; на Linux — xdg-open, на Windows — start
```

Никаких сторонних зависимостей не требуется, нужен только Python 3.10+.
